# ვეფხისტყაოსანი ტურინგის მანქანაზე

ეზოტერიკული პროგრამირების ენების უმეტესობა ტურინგ-სრულია (Turing complete), რაც ნიშნავს, რომ მათ თეორიულად ნებისმიერი გამოთვლადი (computable) რამის გამოთვლა შეუძლიათ. თუმცა, ისინი გამიზნულად არიან სინტაქსურად უცნაურები და შეზღუდულები. ეს პროექტი დაწერილია Brainf*ck-ზე - ალბათ ყველაზე ცნობილ ეზოტერიკულ ენაზე, თავისი სახელის, კომპილატორის მცირე ზომისა და მხოლოდ 8 სიმბოლოსგან შემდგარი სინტაქსის გამო.

ცხადია, მთლიანი ტექსტი ხელით არ მითარგმნია. ენა დამოუკიდებლად ვისწავლე - ძალიან მარტივია, თუმცა ელემენტარული კოდის დასაწერადაც ბევრი დროა საჭირო. ამიტომ, ამხელა ტექსტის დასაბეჭდად გამოვიყენე Claude Opus 5.5, რომელსაც მივაწოდე ტექსტი და აღვუწერე კოდის წერის სტილი, მეთოდოლოგია და ის, თუ როგორ ეთარგმნა ზოგიერთი ქართული ასო, რომელსაც ლათინურ ანბანში ზუსტი შესატყვისი არ გააჩნია.

## კოდის ლოგიკა

კოდი ორი ნაწილისგან შედგება:

1. **სიმბოლოების ინიციალიზაცია (მხოლოდ ერთხელ).** მე-0 უჯრა ციკლის მთვლელია: მასში ვწერ 17-ს, ციკლი კი 1-37 უჯრებს 17-ის ჯერადებით ავსებს. ციკლის შემდეგ თითოეულ უჯრას რამდენიმე `+`-ით ან `-`-ით ზუსტ მნიშვნელობამდე ვასწორებ. მაგალითად, `A`-ს (ASCII კოდში 65-ით გამოისახება) უჯრა ციკლში `++++`-ს იღებს (4 * 17 = 68), შემდეგ კი `---`-ით 65-მდე სწორდება. 17 იმიტომ შევარჩიე, რომ ის ინიციალიზაციის ყველაზე მოკლე კოდს იძლევა: მთვლელის მცირე მნიშვნელობისას ციკლში ბევრი `+` გროვდება, დიდისას კი - ბევრი შესწორება. 2-დან 59-მდე ყველა მნიშვნელობიდან 17-მა სულ 309 `+`/`-` მოგვცა (10-ით 351 იქნებოდა, 8-ით - 389). შედეგად, თითო უჯრაში თითო სიმბოლო ინახება: ინგლისური ანბანის 26-ვე ასო, ჰარი (space), ახალი ხაზი (newline) და პუნქტუაციის ნიშნები `! " ' , - . : ; ?`.
2. **ბეჭდვა.** დანარჩენი კოდი მხოლოდ `>`, `<` და `.` ბრძანებებისგან შედგება: მაჩვენებელი საჭირო სიმბოლოს უჯრაზე გადადის და მას ბეჭდავს. კოდის თითოეული ხაზი ლექსის ერთ ხაზს ბეჭდავს.

მეორე მეთოდი, სადაც ყოველი სიმბოლო ცალ-ცალკე, ნულიდან აიგება ერთსა და იმავე უჯრაში და დაბეჭდვის შემდეგ უჯრა სუფთავდება (`[-]`), დაახლოებით 9.4 MB ზომის კოდს მოგვცემდა, ამიტომ პირველი მეთოდი ავირჩიეთ. გარდა ამისა, უჯრების თანმიმდევრობა ისეა შერჩეული, რომ ტექსტში ხშირად მეზობლად მდგომი სიმბოლოები ერთმანეთთან ახლოს იყოს. ასე მაჩვენებელი ნაკლებს მოძრაობს და ფაილის ზომა ანბანური რიგის ~4 MB-დან ~2.2 MB-მდე მცირდება.
